# QuickFIX Agent Guidelines

QuickFIX is a C++17 implementation of the FIX (Financial Information eXchange) protocol,
supporting FIX 4.0 through 5.0 SP2 and FIXT 1.1, with SWIG bindings for Python 3 and Ruby.

## Generated paths — read this first

Several directories are **build output** and are gitignored. Editing them is silently
undone by the next build:

| Path | Generated by | Edit instead |
|------|--------------|--------------|
| `include/quickfix/` | `cmake/QuickfixPrebuildSetup.cmake` copies `src/C++/*.h` on every build | `src/C++/*.h` |
| `lib/` | all CMake targets land here | — |
| `test/cfg/at.cfg` | `test/setup.sh <port>` | `test/setup.sh` |
| `store/`, `test/store/` | FileStore output at runtime | — |

`include/quickfix/` is **not** the source of the public headers — it is a copy. It is also
excluded from formatting by `.clang-format-ignore`. The installed headers come from
`src/C++/CMakeLists.txt` (`install(DIRECTORY src/C++/ DESTINATION include/quickfix ...)`).

## Build

```bash
# Configure (from repo root)
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release

# Build
cmake --build build
```

**Binaries and libraries are written to `lib/`, not `build/`** — `CMAKE_RUNTIME_OUTPUT_DIRECTORY`
and friends are pointed at `${CMAKE_SOURCE_DIR}/lib` in `CMakeLists.txt`. `build/` holds only
objects and makefiles. So the test binaries are `lib/ut`, `lib/at`, `lib/pt`; `test/ut`,
`test/at` and `test/pt` are symlinks to them, created by the build.

CI configures **in-source** (`cmake . -DCMAKE_BUILD_TYPE=...`), not into `build/`.

### CMake options

| Option | Default | Notes |
|--------|---------|-------|
| `HAVE_SSL` | OFF | |
| `HAVE_MYSQL` | OFF | |
| `HAVE_POSTGRESQL` | OFF | |
| `HAVE_ODBC` | OFF | |
| `HAVE_PYTHON3` | OFF | Builds the SWIG Python 3 bindings (`lib/_quickfix.so`) |
| `QUICKFIX_SHARED_LIBS` | **ON** | Already on; the useful form is `=OFF` for a static build |
| `QUICKFIX_EXAMPLES` | **ON** | Also gates the `at` and `pt` binaries |
| `QUICKFIX_TESTS` | **ON** | Gates **only** `ut` |

Gotcha: `-DQUICKFIX_EXAMPLES=OFF` silently removes the acceptance (`at`) and performance
(`pt`) binaries, because those live under `src/`, not under the test directory.

### Autotools (legacy)

```bash
./bootstrap && ./configure && make && make check
```

CI configures with `--with-python3 --with-ruby --with-openssl`. Note `configure.ac`
mandates only C++11 (`AX_CXX_COMPILE_STDCXX([11],...)`) while CMake requires C++17 —
if you use a C++17 feature, the autotools build can still succeed by accident on a
compiler defaulting to a newer standard.

## Tests

**There is no `test` target.** The repo has no `enable_testing()` / `add_test()`, so
`cmake --build build --target test` does nothing and `ctest` reports zero tests. Run the
suites directly.

| Suite | Binary | What it is |
|-------|--------|------------|
| Unit | `lib/ut` | Catch2 tests; sources in `src/C++/test/` |
| Acceptance | `lib/at` + Ruby | `at` is the acceptor **server**; the tests are Ruby `.def` scripts driven by `test/Runner.rb` |
| Performance | `lib/pt` | Catch2 benchmarks. Built in every configuration; CI only *runs* it for Release |

All of these must be run **from the `test/` directory**:

```bash
cd test

# Unit. Both arguments are required: without --quickfix-spec-path every data
# dictionary lookup resolves to "/FIX4x.xml" and ~16 cases fail spuriously.
./runut.sh
../lib/ut --quickfix-config-file cfg/ut.cfg --quickfix-spec-path ../spec   # equivalent

# Performance
./runpt.sh
../lib/pt --quickfix-spec-path ../spec -# "~[network]"                     # non-network
../lib/pt --quickfix-spec-path ../spec -# "[network]" --port 6668          # network

# Acceptance (starts its own `at` server on the given port)
./runat.sh 6666
```

Prefer the `run*.sh` wrappers: they locate the binary and pass the required arguments.
In particular, under **autotools** `test/ut` is a symlink to `src/ut`, which is a stub
whose `main()` just returns 0 — running `./test/ut` there passes without testing
anything. `runut.sh` knows to prefer the real binary in `src/C++/test/`.

`runat.sh` takes a single argument, the port, and exits non-zero if any group failed. It
prints one `group: ok` line as each of the nine groups completes, then the full per-group
output at the end — the detail is buffered so that nine concurrent writers do not
interleave. A full run is ~60s and 468 tests.

Do **not** wrap `runat.sh` in `setsid`: `setsid` forks and its parent returns immediately,
so the run detaches and appears to succeed instantly while still executing.

### Ports

`runat.sh <port>` needs that port free, and refuses to start if something is already
listening (it would otherwise test against a foreign server's session state). CI uses a
per-configuration offset:

| Use | Port |
|-----|------|
| Acceptance (CI) | 6666 Debug / 6667 Release |
| `pt` network benchmark (CI) | 6668 Debug / 6669 Release |
| `make check` | 54321 |
| bare `pt`, no `--port` | 54322 |

## Code Style

Formatting is enforced by `.clang-format` (2-space indent, no tabs, 120-column limit,
attached braces). CI checks **`src/` only** (`.github/workflows/format.yml`), excluding
`catch_amalgamated`, `pugixml`, `scope_guard` and `UtilitySSL.h`.

Before committing, format only the sources you changed under `src/`:

```bash
git diff --name-only | grep -E '^src/.*\.(cpp|h)$' | xargs -r clang-format -i
```

Do not run clang-format over `include/` — it is generated and `.clang-format-ignore`
excludes it.

Includes: `IncludeBlocks: Preserve`, so existing blocks are not regrouped; the
corresponding header does sort first for a `.cpp` file.

## Naming Conventions

| Element | Style | Example |
|---------|-------|---------|
| Classes / types | PascalCase | `SessionID`, `SocketAcceptor` |
| Methods / functions | camelCase | `sendMessage()`, `getSessionID()` |
| Member variables | `m_` prefix + camelCase | `m_sessionID`, `m_port` |
| Macros | `UPPER_CASE` | `EXCEPT`, `NOEXCEPT`, `HAVE_SSL` |
| Namespace | `FIX` | `namespace FIX { ... }` |

All production code lives in the `FIX` namespace.

## Header Files

- Use **include guards**, not `#pragma once` — this is the established convention
  (76 of 78 headers). Form: `#ifndef FIX_SESSION_H` / `#define FIX_SESSION_H` /
  `#endif // FIX_SESSION_H`.
- One class per header as a general rule (`Exceptions.h` is a deliberate exception).
- Inline simple accessors directly in the class body.
- Mark all non-mutating methods `const`.

## C++ Standards

- Minimum **C++17** under CMake (`set(CMAKE_CXX_STANDARD 17)`).
- Use RAII; prefer `std::unique_ptr` / `std::shared_ptr` over raw owning pointers.
- Use move semantics where appropriate.

## Error Handling

Exception *types* are plain structs deriving from `FIX::Exception`, declared in
`src/C++/Exceptions.h`:

```cpp
struct FieldNotFound : public Exception { ... };
```

`EXCEPT` is a separate compatibility macro defined in `src/C++/Except.h`. It documents
which exceptions a function may throw:

```cpp
void fromApp(const Message& message, const SessionID& sessionID)
    EXCEPT(FieldNotFound, IncorrectDataFormat, IncorrectTagValue, UnsupportedMessageType);
```

Under C++17 `EXCEPT(...)` **expands to nothing** — dynamic exception specifications were
removed from the language, so it survives only for older compilers. Treat it as
documentation, not enforcement. Do not silently swallow exceptions; propagate or log them.

## File Layout

```
src/C++/            Core implementation AND the authoritative public headers
src/C++/test/       Unit tests (Catch2)
src/at.cpp, pt.cpp  Acceptance server and performance benchmark
src/python3/        Python 3 SWIG bindings (src/python/ is legacy Python 2, not built)
src/ruby/           Ruby SWIG bindings
src/swig/, src/sql/ SWIG interface files, SQL schemas
test/               Ruby acceptance harness (Runner.rb, definitions/, run*.sh)
test/cfg/           ut.cfg is tracked; at.cfg is generated by setup.sh
spec/               FIX XML specification files
examples/           Sample applications (executor, ordermatch, tradeclient)
doc/                Hand-written HTML documentation plus a Doxyfile
bin/, cmake/, m4/, scripts/   Helper scripts and build machinery
include/, lib/      Generated — see "Generated paths" above
```

## Documentation

Public API changes must include Doxygen-style comments (`///` or `/** */`).

`doc/html/` is **hand-written and tracked in git** (66 files) — notably
`configuration.html` and `building.html`. User-visible changes (new settings, new
features) require updating the relevant page there by hand. Doxygen (`cd doc && ./document.sh`)
reads `../src/C++` and is a separate API reference.

## CI / PR Checklist

- `clang-format` passes for files under `src/` (CI enforces this on every PR).
- The suites you can affect pass locally — see **Tests** for the real commands.
- Documentation updated for any user-facing change.
- No breaking API changes without discussion.

What CI actually runs:

- **`build_test_cmake.yml`** — {windows, ubuntu, macos} x {Debug, Release} x {SSL off, on}.
  `ut` runs on every leg. `pt` runs only for Release. **The acceptance suite runs only on
  `pull_request` events** — a push to master never runs it.
- **`build_test_autotools.yml`** — ubuntu/macos with gcc and clang; `make check`.
- **`format.yml`** — clang-format over `src/`.

No workflow sets `-Werror` or `/WX`, so new warnings will not fail CI on their own; avoid
introducing them regardless (especially size_t narrowing on MSVC).
